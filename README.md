# Shipyard

A project tracker for developers: create projects, break them down into tasks (feature, bugfix, improvement, chore, other), organize them on a kanban board and follow their progress from a dashboard.

Today Shipyard is a **local-first web app** (data stored in IndexedDB). It is designed to be packaged later with **Electron** (desktop) and **Capacitor** (Android/iOS), and to move to a **remote database** without touching the UI.

## Quick start

Requirements: Node.js ≥ 22.

```bash
npm install
npm run dev        # http://localhost:5173
```

| Script | Description |
| --- | --- |
| `npm run dev` | Vite dev server with HMR |
| `npm run build` | Typecheck + static build in `dist/` |
| `npm run preview` | Serve the production build |
| `npm test` | Unit tests (Vitest + fake-indexeddb) |
| `npm run typecheck` | TypeScript type checking |
| `npm run lint` | Lint with oxlint |
| `npm run format` | Format with Prettier |

## Features

- **Projects**: name, description, color, repository and live site links; archive and delete.
- **Tasks**: type, status (Backlog → To do → In progress → Done), priority, due date, description.
- **Kanban board** with drag & drop (mouse, touch with press-and-hold, keyboard with Space) and a sortable **list view**.
- **Filters** by text, type and priority, kept in the URL.
- **Dashboard**: completion percentage, counts by status and type, overdue and upcoming tasks.
- **Backup**: JSON export/import (*merge* or *replace*) and data reset.
- Light/dark/system theme, responsive layout (sidebar on desktop, bottom navigation on mobile), English UI with i18n ready for more languages.

## Architecture

```
src/
  app/          # entry, providers, router, layout, theme
  components/   # shared components (+ ui/ generated by shadcn)
  domain/       # model: constants, Zod schemas, pure logic (ordering, backup)
  data/         # repository interfaces + Dexie implementation, query keys
  features/
    dashboard/  # statistics (tested pure functions) and page
    projects/   # pages, form, card, TanStack Query hooks
    tasks/      # kanban board, list, filters, form, hooks
    settings/   # theme, export/import, reset
  i18n/         # configuration and translations
  lib/          # utilities (id, dates, download)
```

Key principles:

- **The UI does not know about storage.** Components only use TanStack Query hooks, which receive the repositories (`src/data/repositories.ts`) through a React provider. Switching to a remote backend means providing a new implementation in `createRepositories()` (`src/data/index.ts`).
- **Sync-ready data**: UUID ids, ISO `createdAt`/`updatedAt` timestamps, soft delete via `deletedAt`.
- **Kanban ordering** uses a fractional `order` with automatic column renumbering when precision runs out (`src/domain/task.ts`).
- Pure logic (ordering, statistics, backup, drag & drop position mapping) is separated from components and covered by unit tests.

## Roadmap

- **Desktop (Electron)**: load `dist/` with `VITE_ROUTER_MODE=hash`; replace `src/lib/download.ts` with a native save dialog.
- **Mobile (Capacitor)**: `npx cap add android` / `npx cap add ios` with `webDir: dist`. iOS may evict WebView storage: consider a SQLite repository or remote sync.
- **Remote database**: a new repository implementation (e.g. Supabase/Postgres or a custom API) with Dexie as offline cache.
- Route-level code splitting to reduce the initial bundle.
- Italian translation.
